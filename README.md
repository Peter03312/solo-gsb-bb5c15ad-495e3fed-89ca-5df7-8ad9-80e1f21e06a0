# 事故复盘时间线（Incident Timeline）

供小组在**本地协作**使用的事故复盘时间线应用：记录每个事件的**起始时间范围**、
**持续分钟数**以及事件间的**「先于」关系**，系统推算每个事件的**可行时间窗**
并给出完整的**依据链**；支持版本留痕与多人并发编辑保护。

- **服务端**：Python 3.11（仅标准库，零第三方依赖，离线可构建）
- **持久化**：SQLite（`payload` 原始输入与 `result` 推算结果分列保存）
- **前端**：原生 HTML/CSS/JS，浏览器直接访问，无需构建

---

## 一、容器启动（推荐）

```bash
# 构建并后台启动
docker compose up --build -d

# 查看日志（启动时会自动初始化数据库）
docker compose logs -f timeline

# 停止
docker compose down
```

启动后浏览器访问：

> **http://localhost:8800**

首次启动会自动建表，并写入一条「支付网关故障」示例复盘（含一个暂存草稿事件，
可直接体验推算、依据链与草稿行为）。数据存放在 Docker 命名卷 `timeline-data` 中，
容器重建不丢数据。

### 修改访问端口

编辑 `docker-compose.yml` 的端口映射，例如改用宿主机 9000 端口：

```yaml
ports:
  - "9000:8800"     # 宿主机端口:容器端口
```

### 清空示例 / 使用空库启动

将环境变量 `SEED_DEMO` 设为 `0`（仅在数据库为空的首次初始化时生效）：

```yaml
environment:
  SEED_DEMO: "0"
```

## 二、可配置项（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8800` | 容器内 HTTP 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DB_PATH` | `/data/timeline.db` | SQLite 数据库文件路径（父目录自动创建） |
| `SEED_DEMO` | `1` | 数据库为空且首次初始化时，是否写入示例复盘（`1`/`0`） |

> 网页访问端口 = 浏览器访问 `PORT` 经 compose `ports` 映射后的宿主机端口，
> 默认即 **8800**。

## 三、不使用容器，本地直接运行

需 Python 3.11+，无需 pip 安装任何依赖：

```bash
DB_PATH=./data/timeline.db PORT=8800 SEED_DEMO=1 python3 -m app.server
# 访问 http://localhost:8800
```

运行测试：

```bash
python3 tests/test_app.py
```

## 四、功能与使用说明

### 1. 录入事件与原始时间输入

每个事件填写：**最早开始**、**最晚开始**（构成起始时间范围）、**持续分钟数**。
三项中任意一项缺失，事件会被标记为 **⏳ 暂存草稿**：输入被保留，但**不会被删除或
拒绝**；与该事件相连的「先于」关系标记为「暂不参与推算」并注明原因（缺什么字段）。

### 2. 「先于」关系

在关系面板选择「前一事件 → 后一事件」。其约束语义为：

> 前一事件的**结束时刻** ≤ 后一事件的**开始时刻**

即 `后一开始 ≥ 前一开始 + 前一持续分钟数`。

### 3. 可行时间窗与依据链

右侧实时显示推算结果（编辑时防抖预览，不落库）：

- **开始窗口 / 结束窗口**：在输入范围与全部关系约束共同作用下，该事件可能发生的
  最早～最晚时刻；窗口退化为单点表示开始时刻已被约束完全确定。
- **依据链**：展开每个事件卡片可查看时间窗每个边界是如何一步步推出的，例如
  「A 最早开始 08:00 → A 持续 30 分钟 → A 先于 B → 故 B 最早 08:30 开始」。
- 顶部**甘特概览**：条纹段为可行区间，实色为确定时刻，红色段表示该事件卷入冲突。

推算只收紧边界、不会放宽用户输入的范围。

### 4. 修改后重新计算，原始输入与推算结果分离

- 点击 **💾 保存为新版本** 才落库；服务端重新推算并生成新版本号（v1、v2……）。
- 数据库中 **`payload`（原始输入）与 `result`（推算结果）是两列**，互不覆盖；
  历史版本同时保留二者，可随时回看「当时填了什么、系统算出了什么」。

### 5. 约束冲突：保留输入、指出冲突、不得定稿

以下情况都会判定为冲突并在顶部红色横幅列出，可逐条展开查看**冲突事件与依据链**：

- 事件自身的最早开始晚于最晚开始（输入范围矛盾）；
- 「先于」约束无法满足（前一事件最早结束时刻 > 后一事件最晚开始时刻）；
- 「先于」关系形成闭环（A→B→…→A）。

**冲突版本允许保存（输入原样保留），但点击「定稿」会被拒绝（HTTP 422）**，
直到冲突被消除并保存出新的无冲突版本。

### 6. 多人协作：旧版本提交被拒绝

每次保存必须带上所基于的版本号 `base_version`（乐观锁）：

- 若期间已有他人提交了更新版本，本次保存返回 **409 Conflict**，页面弹窗提示
  「版本已过期，请刷新」，并提供本地未保存内容的 JSON 供复制，**绝不覆盖较新记录**；
- 载入最新版本后，可在其基础上重新编辑、再保存为新版本。

### 7. 定稿与历史版本

- **🔒 定稿当前版本**：仅无冲突、含事件的版本可定稿；定稿后再次编辑保存会生成
  新版本并自动取消定稿标记（定稿只代表某个版本的快照结论）。
- **历史版本**：查看每次保存的版本号、状态（无冲突/含暂存/冲突）、作者与时间；
  可把任一旧版本内容载入编辑区，基于当前最新版再次保存。

## 五、HTTP API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/retros` | 复盘列表（含最新版本状态） |
| POST | `/api/retros` | 新建复盘（生成空的 v1） |
| GET | `/api/retros/{id}` | 复盘详情 + 最新版本（payload 与 result） |
| PATCH | `/api/retros/{id}` | 重命名 |
| DELETE | `/api/retros/{id}` | 删除复盘及全部历史 |
| GET | `/api/retros/{id}/versions` | 版本历史（不含大字段） |
| GET | `/api/retros/{id}/versions/{v}` | 单个版本完整内容 |
| PUT | `/api/retros/{id}/versions` | 保存新版本（body：`base_version`、`payload`、`author`）；过期返回 **409** |
| POST | `/api/retros/{id}/finalize` | 定稿；冲突版本返回 **422** |
| POST | `/api/compute/preview` | 仅推算不落库 |

## 六、目录结构

```
.
├── Dockerfile              # 零依赖镜像；启动即初始化数据库
├── docker-compose.yml      # 一键启动 + 数据卷 + 环境变量配置
├── requirements.txt        # 空（仅标准库）
├── app/
│   ├── compute.py          # 推算引擎：时间窗、依据链、冲突/环/草稿
│   ├── db.py               # SQLite：payload/result 分存 + 乐观版本号
│   ├── server.py           # 标准库 HTTP 服务 + JSON API + 静态页面
│   └── static/             # index.html / style.css / app.js
└── tests/test_app.py       # 推算与并发/定稿规则测试
```
